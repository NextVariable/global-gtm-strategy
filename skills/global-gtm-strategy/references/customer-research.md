# 客户需求研究

围绕四个业务问题：谁在什么场景需要并付钱；现在怎样替代；在哪发现/讨论/评估；为什么换或不换。根据决定性未知选择工作流观察、过去行为访谈或购买过程调查，不预设统一数量、天数、奖励和购买阈值。

已有材料先读授权访谈、支持/流失/赢输记录与行为导出；公开资料用于寻找线索和招募，不代替客户研究。访谈对象覆盖使用者、推荐者、评估者、付款者，一个人可多角色。按关键分歧选样本：近期购买、长期留存、流失、没买、使用替代；不要只筛高付费或 Token 用量 Top10。记录样本来源、时间、地区、角色与选择偏差，匿名化。

访谈先说明用途、授权与记录方式；不隐瞒研究身份，不把访谈变成推销/大使招募。请对方讲最近一次真实任务，顺序还原触发 → 输入/工具/人 → 判断与交接 → 产出 → 失败后果。获准后看屏幕、表格或过去记录，区分亲眼观察与口头回忆。问当时试过什么、花了什么、谁推荐、谁评估、谁签字/付款、为何未选另一方案。再问学习/迁移/集成/关系/安全风险、什么条件下宁愿保持现状。提问不先讲产品，不用“你是不是也很痛”。

对未来“愿意付多少钱”“我会买”记为假设线索，不能写订单或转化率。证据可逐步升级为愿意提供任务材料、完成真实试用、引入预算负责人、走采购、付费并持续使用；每步回答不同问题，不设通用同一等级。试验设计要写何种行为能否定价值或购买假设，不以口头好评为成功。

合并观察时保留原话定位、不同角色的分歧和反例；同人重复说三次不是三样本。分别写需求发生频率、实际代价、希望结果、当前方案为何合理、切换触发、阻力、不购买原因。企业自报节省时间不能直接当客户实际 ROI；投诉量不能当总体流失率。

消费 App 增长诊断：理解使用任务和习惯触发，区分免费/订阅、新/老队列、恢复/连续使用、渠道与地区。用授权日志检查流失/续费与访谈能否对应；不把公司 DAU 比值当队列留存，满意度问卷也不是续费证明。B2B 检查预算周期、审查权限、现有合同、实施依赖；开源检查个人试用到团队采购的断点；硬件检查设备设置/携带频率、耗材/订阅实际消耗及退货。

不固定“访谈五人已饱和”或40%PMF通用线。按决定性分歧与新增信息记录是否还需扩大样本，非代表样本不外推总体概率。结束交付角色-工作流-触发-替代-阻力的证据链、明确未验证的付款/留存命题，以及最有价值的补证动作；实际采访未做就不能声称发现客户需求。

## 招募与访谈设计

先写本轮需要区分的命题，例如“个人用户觉得有用，但公司是否允许上传素材并采购”。按这个分歧选择样本；查已授权的使用/付款记录或近期公开相关讨论，筛选问题包括最近一次任务时间、实际负责哪一步、当前方案、数据/设备使用权限、是否参与购买、能否演示去敏后的实际工作流。不因职位、粉丝数或回复热情就判为合格客户。

设计简洁邀约，说明身份、为什么该人的经历相关、讨论什么、预计时间、是否补偿，以及记录用途。补偿不得与好评或采购挂钩。仅准备邀约资料；实际发送需在已授权的联系范围内。记录邀请、回复、合格、参加、退出及原因，检查样本偏差，不用回复率代替需求。

把访谈问题按目标选用，不必全部问完。开场确认用途和记录同意，可以只记笔记；拒绝录屏不等于无效样本。

| 目标 | 提问与追问 | 要取得的材料 |
|---|---|---|
| 最近任务与代价 | 最近一次是什么时候？从哪里开始、交给谁、什么结果才算完成？失败发生过什么？ | 过去任务、输入输出、实际频率和后果 |
| 当前替代 | 当时具体用了什么？试过哪些方案又放弃了？花费、维护和人工时间如何得知？ | 操作或记录，支出来源，保留现状的理由 |
| 发现与购买 | 当时为什么开始找？在哪里看到、怎样比较、谁评估和付款？最后为什么选/没选？ | 触发事件、渠道、角色、采购条件与时间线 |
| 切换阻力 | 如果换方案，哪些数据、工具、人和流程要一起改变？哪一步由谁批准？ | 迁移、授权、实施、预算和现有合同约束 |
| 已使用后的变化 | 哪一步改变、哪一步没改变？是否仍需返工？能否看一个前后任务？ | 真实结果与剩余工作，不以口头节省时间作ROI |
| 流失或放弃 | 最后一次使用时发生什么？现在怎样解决？还有哪些原因，即使修好该问题也不会回来？ | 最后任务、替代、性能/流程/画像/预期原因 |

## 完整任务观察

根据真实场景设计输入 → 核心处理 → 判断/修改 → 组织 → 导出或下游交接的完整任务，而不是逐个点击功能。先记录用户原有期望，再观察体验，避免体验反过来改写期望。说明观察的是产品和流程，不是考核用户；邀请边做边说，卡住时先观察再帮助，记录帮助是否改变了结果。

把价值问题、体验问题和功能缺口分开：价值用过去任务与结果比较，体验看实际操作与等待，缺口记录未完成环节和重现步骤。任务负载尽量接近实际，但不要求导入未获授权的客户素材。收集环境、文件/数据规模和任务条件；提供示例输入或指导时，标记受帮助的表现，不能声称独立完成。

逐步记录：时间/任务步骤、用户操作、原话及定位、系统反馈、等待或错误、是否需要协助、最终产出和是否能被下游使用。加载空档可了解角色和原有工具，不打断关键操作。结束询问最有价值、最困惑的部分、未解决任务和采购顾虑；未来价格回答只作线索。

## 记录、综合与决策回流

单次记录包含匿名ID、样本来源、地区/语言、角色、任务与采购参与、权限、环境、记录同意、来源文件与定位。把原话、亲眼观察、研究者解释和待验证命题分栏；每个发现独立关联来源，另列相反发现、替代优势、未解决步骤及下一动作。故障另记操作 → 期望 → 实际 → 环境，不将所有故障归为没有需求。

按场景、任务权限、发生频率和购买角色汇总，而不是只按职位。项目制用户可能随项目结束不再使用；执行者可能没有公司素材或预算权限；使用者与老板的诉求不同。记录同意试用、安装、首次完成、重复使用、购买流程的阶段与退出原因；每步分母和时间窗独立定义，不将它们当一个转化率。

对主题记录“哪些独立样本提到/有多少可比较样本”、是否自发提出、实际代价、反例和证据缺口。保留原始计数，不把便利样本频率外推总体。表达、使用和购买结果冲突时先解释样本、时间和场景，不能挑支持产品的片段。停止或扩样取决于关键分歧是否仍影响选择与剩余研究资源；尚未覆盖付款角色时不能宣布采购已验证。

最后更新候选客户范围、不适合的用户、切换和购买条件、定位可用原话及禁止宣称项。功能请求记录为解决某任务的候选方案，不直接代替产品优先级。对外使用引语或客户案例另需相应用途许可；本模块的研究同意不自动包含公开宣传。
