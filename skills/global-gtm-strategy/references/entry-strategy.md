# 市场进入策略与下一验证

输入是候选排序、客户工作流/角色、替代取舍、交付与商业条件。先明确目标用户、价值、差异、证明：对谁在什么触发时改变什么结果，相比现在方案何处不同，我们实际能证明什么。没有真实效果证明写待验证价值，不能从模板生成节省百分比。详细文案交第二个 Skill。

从购买过程决定进入方式：用户能自行试用并买单可考虑自助；团队需安全/预算审批则安排技术评估与采购证明；高实施依赖需顾问/合作伙伴；开源的开发者采用可以连到托管/支持/企业服务，但先核对许可证与付费路径；硬件看直销/经销/企业试点与交付服务。可组合但不按 ARR 阈值自动选 SLG 或强推 PLG。

说明如何触达(具体群体与已有聚集/查找证据)、如何产生有效评估(真实任务、演示/试用所需条件)、谁决定购买、需要哪种证明与哪些能力。渠道选择须同时满足客户出现/购买意图、团队资源、交付节奏，不能“大家都去PH所以去PH”。没有证据的社区/关键词/伙伴作为探索假设，不声称已经可获客。涉及记录/隐私/当地准入只写已经核实的能力与条件，不代做合规承诺。执行广告、发帖、外联、报价和成交交第三/第四个 Skill。

选择一项优先验证关键未知的动作，成本/周期符合本项目资源。写对象及筛选、要观察的行为、资料/时间/人员预算、结果口径、基于业务约束的继续/修改/停止条件与负责人(未知则角色待指定)。不强行设5访谈/20%转化/某国先行；若拟定阈值是试验设计，解释容错与最小有用结果，不作统计显著或行业标准。无客户也可先招募并核对过去任务/替代购买；口头愿购不算付款验证。实验实施/统计复盘交第五个 Skill。

继续条件须对应本轮要验证的命题：任务演示回答能否完成，第二次真实使用回答是否复用，预算负责人参与回答购买路径是否存在，结算后未退款的付款回答本次成交，续费回答该期间持续购买。不能让“愿意谈报价”通过收入验证，也不能让“一次试用成功”通过留存验证；早期只验证招募或工作流时也不强行要求付款。下一项补证按可能改变选择的程度、取得难度和剩余资源确定，不能每次都收敛成一套访谈加试用。

合成输入的演示只能证明该演示条件下流程可运行，不能单独证明真实客户任务价值、实际采用或准入。去敏后的真实任务应保留任务来源、约束及下游验收范围；匿名不等于模拟。说明本轮实际观察到哪种结果，不把演示成功扩大为客户价值已经验证。

暂不能决定时也应缩小决策：先补何种证据、为何最有价值、得到不同结果分别如何选。条件推荐必须说“如果X成立则Y”，记录X未证实。反对证据不能放附录后继续无条件推荐；列触发撤回的功能/成本/采购/留存/准入变化。

使用 [handoff.md](../templates/handoff.md)，引用 context 与决定性 claim/evidence ID，不复制猜测成事实。第二 Skill接目标/价值/差异/证明和禁止宣称项；第三接市场/触达机制/渠道假设与资源边界；第四接角色/触发/评估与购买流程/不买理由；第五接下一验证/口径/停止条件。交接明确哪些可复用、哪些要刷新、哪些未验证。不执行后四个 Skill，也不创建它们的空目录。
