# 商业机会评估

先问规模估算会改变选择吗：是否需支持某销售成本/产能投入，是否足够一小组试验，或两个候选需要比较。不会改变就说明未估算，优先补需求/购买证据。不要无来源引用“千亿美元市场”，不要假定拿1%即可。

若需要，明确地区/语言/客户资格、单位(客户/设备/人/付费席位)、时间、币种、收入定义。自下而上可为合格账户区间 × 每账户年支出区间；每项有来源、日期、范围与假设。官方统计分类可能比真实细分宽，给筛选依据与未知，不凭空砍比例。自上而下只能作带适用限制的交叉检查，搜索量/流量不能直接换算付费人群。供应商市场报告数字无法找到方法或原文时列未验证，不带入模型。

可获得收入从可达性与能力约束推导：期限内能接触的合格账户、完成评估的能力、试验支持的采购概率区间、实施/库存/服务上限和现实周期。没有获客/成交数据就做条件情景，不能作为预测。不得从 TAM 取任意份额制造 SOM。销售漏斗概率来源可为本项目历史同队列；跨行业经验仅是标注假设。硬件一次性收入、实施费与订阅 ARR 分开；合同 pipeline 不等于收入，年付实收不等于当期确认收入。

硬件订单的预售、发货、签收、验收和续费分别记录；物流发货记录不能证明客户已收到或接受设备，也不能解除后续退款与履约成本的不确定性。

脚本 `opportunity_math.py` 只做非负区间乘法与逐项敏感性，输入 [sizing-input.json](../templates/sizing-input.json)；它不生成市场份额、概率或证据。区间端点包络不是置信区间，假设独立组合可能不可实现，检查变量相关性。每个驱动写 source_ids 或 hypothesis_id，单位在公式中可消去；缺来源时输出仅为情景。逐项变动后若推荐改变，优先验证该变量，而非提供单点精度。

商业检查还包括谁出预算、替代支出、获得价值的周期、采购/实施周期、支持/算力/供应链/退货/迁移成本及团队可交付能力。有实际队列才算 CAC/留存/毛利；早期不能默认 LTV=ARPA/churn 或 LTV/CAC>3证明可行。硬件看设备毛利与服务消耗/续费分别；消费 App 看免费与付费留存及退款；开源看生产采用与付费升级断点。没有真实成本用范围假设并写盈亏/产能撤回条件。

比较具体候选时，将收入与成本对齐到同一客户单位、币种和期间。每期贡献 = 可保留收入 − 随该客户增加的算力、服务、交付、支付、退款等成本；团队工时是否计入要说明，不把贡献称为扣除全部固定费用后的净利润。获客一次性投入与持续服务成本分开；年付现金、确认收入与ARR也分开。算力价格看实际计费单位、用量上限及重试，不只看标价。若某候选每增加一个客户就扩大亏损，或实施与支持占满产能，不能只因收入或意向更多就优先。

可交付客户数受可用工时/每客户所需工时、库存及并行实施限制；销售周期和收款时间需落在现金可支撑窗口内。用可核实的报价、试验耗用或历史记录算相应边界，未知量写情景。明确“成本降到多少、价格或采用量达到多少才值得继续”，不要统一套用某个CAC、毛利率或回本月数。已有队列的比较还应检查取消、退款与持续价值；单月贡献更好不自动证明长期更好。

结尾判断 opportunity 是有证据进入、条件试验、还是暂不能决定；写支持/反对、不可承受的条件和哪项补证会改变判断。资金/法规/税收若决定准入需当前官方核验，不能引用成长故事作为政策保证。
